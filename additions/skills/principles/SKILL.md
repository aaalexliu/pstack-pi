# Principles

Pick the principle that fits the moment and read its `SKILL.md` in full before you apply it. Do not read them all. Paths are relative to the pstack-pi package root, three directories above this file.

- `principle-attack-the-premise`: two fixes on one premise failed the same gate. Read `skills/principle-attack-the-premise/SKILL.md`.
- `principle-boundary-discipline`: placing validation, error handling, or adapters. Read `skills/principle-boundary-discipline/SKILL.md`.
- `principle-build-the-lever`: non-trivial work a script or tool could do or prove. Read `skills/principle-build-the-lever/SKILL.md`.
- `principle-encode-lessons-in-structure`: the same instruction or correction keeps coming back. Read `skills/principle-encode-lessons-in-structure/SKILL.md`.
- `principle-exhaust-the-design-space`: a novel UI or architecture call with no precedent. Read `skills/principle-exhaust-the-design-space/SKILL.md`.
- `principle-experience-first`: product, UX, or scope tradeoffs. Read `skills/principle-experience-first/SKILL.md`.
- `principle-explain-the-number`: measuring, or trusting a measured number. Read `skills/principle-explain-the-number/SKILL.md`.
- `principle-fix-root-causes`: debugging. Read `skills/principle-fix-root-causes/SKILL.md`.
- `principle-foundational-thinking`: choosing core types and data shapes before logic. Read `skills/principle-foundational-thinking/SKILL.md`.
- `principle-guard-the-context-window`: context is filling up with large output. Read `skills/principle-guard-the-context-window/SKILL.md`.
- `principle-laziness-protocol`: refactoring or tempted to add a layer. Read `skills/principle-laziness-protocol/SKILL.md`.
- `principle-make-operations-idempotent`: steps that must survive crashes and retries. Read `skills/principle-make-operations-idempotent/SKILL.md`.
- `principle-migrate-callers-then-delete-legacy-apis`: a new internal API while old callers remain. Read `skills/principle-migrate-callers-then-delete-legacy-apis/SKILL.md`.
- `principle-minimize-reader-load`: code that is hard to trace. Read `skills/principle-minimize-reader-load/SKILL.md`.
- `principle-model-the-domain`: stateful or branchy logic. Read `skills/principle-model-the-domain/SKILL.md`.
- `principle-never-block-on-the-human`: tempted to ask before reversible work. Read `skills/principle-never-block-on-the-human/SKILL.md`.
- `principle-outcome-oriented-execution`: planned rewrites and migrations. Read `skills/principle-outcome-oriented-execution/SKILL.md`.
- `principle-prove-it-works`: before declaring work done. Read `skills/principle-prove-it-works/SKILL.md`.
- `principle-redesign-from-first-principles`: fitting a new requirement into an existing design. Read `skills/principle-redesign-from-first-principles/SKILL.md`.
- `principle-separate-before-serializing-shared-state`: concurrent writers to one file, branch, or key. Read `skills/principle-separate-before-serializing-shared-state/SKILL.md`.
- `principle-sequence-verifiable-units`: multi-step work and stacking commits or PRs. Read `skills/principle-sequence-verifiable-units/SKILL.md`.
- `principle-subtract-before-you-add`: ordering an addition, refactor, or rewrite. Read `skills/principle-subtract-before-you-add/SKILL.md`.
- `principle-test-behavior-not-implementation`: writing, changing, or keeping a test. Read `skills/principle-test-behavior-not-implementation/SKILL.md`.
- `principle-type-system-discipline`: designing types or signatures. Read `skills/principle-type-system-discipline/SKILL.md`.
